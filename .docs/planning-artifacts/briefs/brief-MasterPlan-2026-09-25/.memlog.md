- (decision) Product name is MasterPlan; Singleton is the group name (IBE160 G30), not the product.
- (decision) Concept: planning/organization platform for individuals and groups - tasks, activities, everyday life and special events; core pain is info scattered across messaging apps, notes, platforms.
- (event) Origin: FD's passion for planning plus a recent major event where coordination was spread across many channels and hard to track.
- (decision) Form factor: web app first; mobile app is an aspiration for a later version.
- (decision) Course must-haves known so far: database and login.
- (assumption) Target audience as stated is very broad (students, professionals, individuals, event planners, families) - flagged for narrowing.
- (event) Competitive landscape research captured in addendum.md: market is crowded and split by event type; gap is combining everyday tasks with one-off group events; guest access without an app and AI chat-to-tasks look like baseline expectations.
- (decision) Primary audiences: (a) professional organizers/planners (wedding planners, event management) and (b) private individuals running an event without professional competence. Tension between the two flagged.
- (event) Core failure at FD's event: people forgot their assigned tasks, no follow-up happened, causing stress and chaotic parts of the event. Points to task ownership/accountability/follow-up as the core problem.
- (decision) AI is both a product feature in MasterPlan and a tool used to build it (course: Programmering med KI). Specific AI feature not yet defined.
- (decision) Post-event evaluation template is a wanted feature: users evaluate the event and learn what to do better next time.
- (assumption) Focus appears to have shifted from everyday life + events to events specifically; needs confirmation whether everyday task management is dropped from v1.
- (decision) V1 primary audience: private individuals organizing an event without professional competence. Professional planners parked for later vision.
- (decision) Everyday-life task management cut from v1 - MasterPlan is event-focused (Todoist/Google own everyday tasks).
- (decision) AI features for v1: (a) plan generator from event description to tasks with deadlines, (c) AI evaluation summary feeding improvements into next plan. Rejected for v1: follow-up assistant (b), chat-to-tasks (d, commoditized).
- (event) Working mode: coaching path chosen.
- (decision) Primary persona: maid of honor with stressful private life, low planning competence/dislikes organizing; plans bachelorette (15 guests, 6 months out) and wedding (80 guests, 8 months out) with 5 helpers.
- (decision) Helper access: link for quick access to their tasks, plus optional own login so helpers can join brainstorming and co-create the plan.
- (decision) Anti-forgetting mechanism: automatic reminders, organizer overview of task status, helpers explicitly confirm/accept each task.
- (decision) Reminder tone: personal and humorous, making participation in planning a big event fun rather than a chore.
- (decision) V1 includes a cross-event overview: organizer can run multiple overlapping events (bachelorette + wedding) and see what is due across all of them.
- (override) AI reminders brought back into v1 (previously rejected option b): AI writes personalised reminder messages to each helper - because follow-up is the core problem and fixed templates would feel repetitive.
- (change) Reminder tone changed from humorous to personal, respectful and direct - like a good manager speaking to a team member. Avoids jokes reading as passive-aggressive on overdue tasks.
- (decision) Helpers answer each task yes or no, can change their answer later, and can send a message back to the organizer - so declined/at-risk tasks surface early.
- (decision) Evaluation value: tool for everyone involved in planning (organizer may do this again, may even come to enjoy planning); plus mid-planning evaluation checkpoints (e.g. after bachelorette, before wedding).
- (decision) Experience bank: AI aggregates evaluations into anonymised best practice reused across all MasterPlan users; must not contain personal details, only general experiences and best practice.
- (decision) Brainstorming wishes: idea suggestions, voting, comments on tasks and plans, shared idea board, shared colour palette board, visual identity. Flagged as scope risk - needs prioritising for v1.
- (event) Capacity: FD is working alone on the project (group Singleton = one member). Deadline not yet stated.
- (decision) V1 brainstorming limited to idea suggestions and comments on tasks/plan. Voting, shared idea board, colour palette board and visual identity moved to later versions.
- (decision) V1 core chain agreed: create event -> AI drafts plan -> assign tasks to helpers via link -> helpers answer yes/no -> AI reminders -> organizer overview -> evaluation. Plus: event-type templates (e.g. bachelorette, wedding, birthday) as starting points.
- (decision) Deadline: November 2026 (end of semester), ~2 months from 2026-09-25, solo. Reflection report due later in semester.
- (decision) Experience bank: v1 = minimum (evaluations stored anonymised, AI can use them); full version (AI actively drawing on cross-user lessons when drafting plans) goes to Vision.
- (decision) Guest list included in v1 (relevant for planning). Budget, cost-splitting and RSVP moved to Vision.
- (decision) Reminders delivered by email only in v1 (SMS costs money / needs paid service).
- (decision) Priority split: must-work = login, events+templates, AI plan, tasks yes/no, AI email reminders, overview, evaluation+AI summary, minimum experience bank. If-time = guest list, idea suggestions + comments.
- (decision) Product validation: FD monitors a test with 2-3 friends running a fake event in the app before the November deadline.
- (event) Course grading captured: 70% code+functionality (AI-generated app; docs must show how AI was used and how code quality was ensured); 30% reflection report (process, challenges, solutions; critical evaluation of AI influence; ethical and technological implications). FD uses AI to write the code.
- (decision) Success thresholds confirmed: 80% of tasks answered yes/no within 3 days; 80% of accepted tasks completed by deadline.
- (decision) Vision order: grow the web platform first (full experience bank, budget, cost-split, RSVP, voting, idea boards, visual identity) before mobile. Goal: user-friendly enough for frequent private use; broad template library reaching new groups (students organizing projects, major events, trips); template marketplace where professional planners sell templates to private individuals.
- (decision) Chat app and calendar integrations moved into v1 (FD's call). Scoped as: add task deadlines to calendar (e.g. Google Calendar / .ics) and share event/task links into chat apps; full two-way chat API integration flagged as heavy for solo 2-month build.
- (change) Helper login wording aligned with scope: helpers can create a login and take part in the plan; brainstorming (ideas, comments) described as planned extra (if-time).
- (event) Finalized: memlog audit completed with FD; structure+prose review applied to brief.md and addendum.md; brief status set to final.
- (change) Brief shortened to 1-2 pages at FD's request; no decisions changed. Detail (persona, helper experience, reminder tone history, evaluation cadence, full ethics, vision detail) moved to addendum.md.
